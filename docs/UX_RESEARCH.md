### 화면 구성 결정

- 편집: 상단 제목·파일 메뉴·공유 버튼, 큰 영상과 우측 소리 조정 패널, 하단 전체 너비 시간축. 세부 파일 관리와 압축 설정을 영상 주변에서 분리했습니다.
- 공유: 대상 선택 → 용량·형식·저장 위치 → 진행·취소 → 완성 파일. 실제 선택 구간의 이미지와 길이를 유지해 무엇을 공유하는지 알 수 있게 합니다.
- Discord 선택은 첨부용 파일을 만드는 안내입니다. 계정 연결·자동 업로드·공유 링크를 추가하지 않습니다. 완료 파일은 끌어서 첨부하거나 파일 복사/폴더 열기로 전달합니다.
- 녹화 화면: 버퍼가 얼마나 쌓였는지, 임시 용량이 얼마나 찼는지를 함께 표시합니다. 숨긴 창과 편집 화면에서는 불필요한 실시간 캡처 미리보기의 UI 복사를 생략합니다.
- 공유 인코딩의 영상 스레드 2개·필터 스레드 1개로 CPU 경합을 제한합니다. 화질 계산·목표 용량 검증은 유지합니다. 이것만으로 게임 FPS 영향이 해결됐다고 주장하지 않습니다.

## 이번 사용성 판단

- 다시 파일을 열 때 매번 같은 구간·볼륨을 맞추는 작업을 줄이기 위해 편집 자동 저장을 추가했습니다. 이것은 위 자료를 바탕으로 한 VideoView 설계 판단입니다.
- 짧은 구간을 여러 번 듣고 음량을 맞추기 쉽도록 구간 반복을 추가했습니다.
- 내보내기 완료 후 탐색기를 자동 실행하면 진행 중인 작업을 방해할 수 있어 사용자가 버튼을 누를 때 열도록 바꿨습니다. 클립 저장도 현재 편집을 강제로 전환하지 않습니다.
- 검색 결과가 없어도 열려 있는 편집은 유지합니다. 빈 보관함은 다음 행동을 안내합니다.
- 작은 창은 미리보기·시간축 높이가 줄어들며 믹서와 내보내기를 유지합니다. 설정 저장은 스크롤과 분리합니다.
- 새로운 편집 정보는 기존 `.recording.json`에 선택 필드로 추가했습니다. 이전 파일도 열 수 있고, 새 버전에서 제목 변경과 편집 저장이 서로 덮어쓰지 않습니다. 원본 바이트는 수정하지 않습니다.

## v0.4에서 반영한 후속 요청

아래 v0.3 후보 중 **긴 파일 부분 미리보기·지속 캐시**와 **녹화 중 전역 중요 순간 표시**를 v0.4에서 구현했습니다. 현재 구간 우선 준비, 파형 분석 분리, 다음 구간 미리 준비, 512MiB 캐시 정리, 원본/믹서 변경과 손상 감지, 녹화 재시작·리플레이·복구 시간축 보정을 포함합니다. 구현·측정 범위는 [VALIDATION.md](VALIDATION.md), 사용 흐름은 [INTERACTION_DESIGN.md](INTERACTION_DESIGN.md)를 참고하세요.

## v0.3 당시 후속 후보와 미해결 항목

- **긴 녹화의 첫 미리보기 지연:** [SteelSeries 재생 지연 지원 문서](https://support.steelseries.com/hc/en-us/articles/40870894510733-Moments-lagging-when-viewing-in-GG)도 이 문제를 다룹니다. 현재 VideoView는 미리보기 혼합 음성과 파형을 준비하므로 긴 파일에는 대기 시간이 있습니다. 지속 캐시·부분 미리보기는 용량 상한과 무효화 검증 후 추가할 후보입니다. 이번 버전이 이를 해결했다고 주장하지 않습니다.
- **녹화 중 북마크 전역 키:** 연속 녹화 재시작·리플레이 저장 시간축과 함께 보존해야 하므로 별도 구현 대상으로 남겼습니다.
- **마이크 무음·클리핑 안내, 짧은 진단 녹화:** 조용한 대화를 오류로 판단하지 않는 기준과 장치 재연결 동작이 필요합니다.
- **노이즈 제거·누르고 말하기, 앱별 프로필, HDR 처리:** 실제 Discord·게임 환경에서 음질·성능을 측정한 뒤 도입할 후보입니다.
- 자동 하이라이트·자동 삭제·계정·클라우드 업로드는 이번 변경에 포함하지 않았습니다.
